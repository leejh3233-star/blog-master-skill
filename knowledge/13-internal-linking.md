# Knowledge — 내부링크 맵·콘텐츠 클러스터

검토 기준일: 2026-09-22
모듈 버전: 1.0.0

## 1. 목적

기존 블로그 글과 새 글 사이에서 독자에게 실제 도움이 되는 관련 콘텐츠를 찾아 자연스럽게 연결한다.

목표는 내부링크 개수 증가가 아니라 다음이다.

관련성 > 독자 도움 > 정확한 URL > 자연스러운 문맥 > 링크 개수

내부링크는 검색엔진을 속이기 위한 장치가 아니다. 관련 글이 없으면 0개가 정상이다.

## 2. 적용 범위

새 글:
- 1단계에서 동일 블로그의 관련 기존 글 후보를 탐색한다.
- 3단계에서 INTERNAL_LINK_PLAN을 설계한다.
- 4단계에서 자연스러운 문맥에 반영한다.
- 5단계에서 실제 URL과 목적지를 재검증한다.

기존 글 최적화:
- 사용자가 내부링크 분석·수정안을 요청하면 기존 글 목록을 훑어 콘텐츠 관계도를 만든다.
- 실제 수정은 사용자가 자동 적용을 요청한 경우에만 수행한다.

## 3. 블로그 경계

프로젝트별 내부링크 장부를 분리한다.

- 맛보고 가이소
- 이코노믹 브리지
- AI 연결소

기본값은 같은 블로그 내부 연결이다. 서로 다른 블로그 간 연결은 사용자가 명시적으로 요청하고 실제 독자 가치가 있을 때만 별도 검토한다.

## 4. 관련성 판정

다음 중 하나 이상이 강하게 성립해야 후보가 된다.

- 같은 주제
- 같은 검색의도의 다음 단계
- 같은 지역
- 같은 방송·프로그램
- 같은 여행 동선
- 같은 AI 도구·업무
- 같은 정책 대상·신청 과정
- 상위 개념 ↔ 상세 설명
- 입문 ↔ 심화
- 문제 설명 ↔ 해결방법
- 비교 글 ↔ 개별 상세 글

같은 단어 하나만 겹치는 약한 관계는 링크하지 않는다.

## 5. 독자 다음 질문

링크 전 다음을 묻는다.

"이 문단을 읽은 독자가 다음으로 무엇을 궁금해할까?"

그 질문에 직접 답하는 기존 글이 있을 때 우선 연결한다.

예:
- 식당 현재정보 → 근처 여행 코스
- ChatGPT 사용법 → 자동화 방법
- 정책 소개 → 신청방법

## 6. INTERNAL_LINK_MAP

가능한 경우 기존 글에서 다음을 수집한다.

- 제목
- 실제 게시 URL
- 게시일
- 핵심 주제
- 메인 키워드
- 검색의도
- 핵심 질문
- 지역·장소
- 방송·프로그램
- 제품·서비스
- 정책·제도
- 글 유형

내부적으로 SOURCE_ARTICLE ↔ TARGET_ARTICLE 관계와 CONNECTION_REASON을 기록한다.

## 7. 후보 등급

STRONG:
직접적인 다음 질문 또는 같은 클러스터.

MEDIUM:
독자에게 실질적인 다음 읽을거리.

WEAK:
키워드 일부만 겹침. 기본적으로 링크하지 않는다.

NONE:
연결 금지.

STRONG과 명확한 MEDIUM만 실제 링크 후보로 사용한다.

## 8. URL 검증

제목만 보고 URL을 추측하지 않는다.

실제 게시글을 열어 다음을 확인한다.

- 글이 존재하는가
- 삭제·비공개가 아닌가
- 같은 TARGET BLOG의 글인가
- 제목과 목적지가 일치하는가
- 다른 글로 잘못 이동하지 않는가

검증된 실제 URL만 사용한다.

## 9. 앵커 텍스트

링크 문구만 읽어도 목적을 이해할 수 있게 한다.

좋은 예:
- 전주 당일치기 여행 코스
- ChatGPT 자동화 시작 방법
- 2026 소상공인 정책자금 신청방법

피할 예:
- 여기
- 클릭
- 관련글
- 자세히
- 이 글

검색어를 억지로 반복하는 앵커 텍스트는 만들지 않는다.

## 10. 삽입 위치

우선 위치:
- 관련 내용을 설명한 직후
- 추가정보가 필요해지는 지점
- 다음 행동을 고민하는 지점
- 글 후반의 자연스러운 관련 콘텐츠 안내

원래 글의 의미를 크게 바꾸지 않는다. 기존 문장을 활용하거나 짧은 연결문장 1~2개를 추가한다.

## 11. 링크 과다 방지

링크 수는 강제하지 않는다.

참고 범위:
- 짧은 글: 0~2개도 정상
- 일반 정보글: 1~4개가 자연스러울 수 있음
- 긴 허브형 글: 필요하면 더 많을 수 있음

이 숫자는 SEO 공식이나 점수가 아니다.

## 12. 기존 링크 보호

공식 링크, 네이버 지도, 예약 링크, 방송·YouTube 링크, 출처 링크를 내부링크로 대체하지 않는다.

이미 같은 목적의 내부링크가 있으면 중복하지 않는다. 같은 URL을 한 글에서 반복할 실질적 이유가 없으면 한 번만 사용한다.

## 13. HUB & CLUSTER

글이 충분히 쌓이면 클러스터를 식별한다.

맛보고 예:
지역 HUB → 방송맛집 / 음식 / 카페 / 여행

AI 연결소 예:
AI 자동화 HUB → ChatGPT / Aside / Plugins / MCP / Agent / 바이브코딩

이코노믹 브리지 예:
소상공인 정책 HUB → 지원금 / 정책자금 / 대상조건 / 신청방법 / 금융·세금

허브를 만들기 위해 빈약한 글을 억지로 만들지 않는다.

## 14. ORPHAN CONTENT

다른 글에서 거의 연결되지 않는 글을 ORPHAN_CANDIDATE로 기록할 수 있다.

고아 글이라는 이유만으로 억지 링크하지 않는다. 실제 관련 글이 있을 때만 연결한다.

## 15. 오래된 글

과거 글을 링크할 때 가격·영업시간·정책·지원금·AI 기능·요금·서비스 명칭 등 변동 정보가 명백히 오래됐으면 OUTDATED_CONTENT 후보로 기록한다.

내부링크 작업이 곧 전체 최신화 작업이라는 뜻은 아니다. 수정 범위를 임의 확대하지 않는다.

## 16. 새 글용 INTERNAL_LINK_PLAN

3단계 내부 산출물 예:

- source: 현재 작성 중인 글
- target_title: 기존 관련 글
- target_url: 검증된 URL
- relation: STRONG / MEDIUM
- connection_reason
- insertion_section
- anchor_text

관련 후보가 없으면 INTERNAL_LINK_PLAN = NONE.

## 17. 5단계 LINK RECHECK

내부링크도 외부 행동 링크와 동일하게 실제 접속을 확인한다.

- URL 정상
- 제목·목적 일치
- 같은 블로그
- 삭제·비공개 아님
- 앵커 텍스트와 목적지 일치
- 중복 링크 아님

FAIL이면 교체 또는 제거한다.

## 18. 기존 글 전체 최적화 모드

명령 해석:

"내부링크 분석만"
→ 전체 관계도와 후보만 제안. 수정 금지.

"내부링크 수정안"
→ SOURCE / TARGET / 위치 / 앵커 / 이유를 제안. 수정 금지.

"내부링크 자동 적용"
→ 검증된 후보만 실제 수정. 계정·제목·URL을 다시 확인한 뒤 적용.

기존 글의 제목·이미지·공식링크·공개설정·카테고리를 임의로 변경하거나 삭제하지 않는다.

## 19. 수정 후 QA

- 원문 의미가 보존됐는가
- 제목·이미지가 유지됐는가
- 기존 공식 링크가 유지됐는가
- 새 내부링크가 정확한가
- 앵커와 목적지가 일치하는가
- 문장이 자연스러운가
- 링크가 과하지 않은가

저장 후 새 링크를 실제로 다시 열어 확인한다.

## 20. 프로젝트별 우선 연결

맛보고 가이소:
같은 지역 / 방송 / 프로그램 / 음식 / 맛집↔여행 / 맛집↔카페 / 과거 방송↔현재정보

이코노믹 브리지:
경제이슈↔정책 / 정책↔대상조건 / 정책↔신청방법 / 지원금↔정책자금 / 제도설명↔행동

AI 연결소:
입문↔활용 / 도구소개↔사용법 / ChatGPT↔자동화 / 자동화↔Agent / MCP↔Plugins / 바이브코딩↔실제개발 / AI이미지↔AI영상

## 21. 최종 원칙

- 관련 글이 있으면 자연스럽게 연결한다.
- 관련 글이 없으면 링크하지 않는다.
- URL을 추측하지 않는다.
- 링크 개수를 목표로 하지 않는다.
- 기존 글을 훼손하지 않는다.
- 독자의 다음 질문을 해결하는 연결을 우선한다.
