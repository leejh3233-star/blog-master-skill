# Knowledge — 이미지 자동 진행

`이미지 자동 진행` 입력 시 **5단계에서 확정된 FINAL_ARTICLE만 기준**으로 설계한다.

기본 수량:
- 대표 1장
- 본문 정보 이미지 3~6장
- 총 4~7장

이미지 수를 채우기 위해 내용을 반복하지 않는다.
정보가 부족하면 4~6장에서 종료한다.

## 1. 먼저 정보 역할을 배정한다
최종 원고의 핵심 정보를 항목별로 분해한 뒤 각 정보를 담당할 이미지 번호를 배정한다.

각 이미지 설계 항목:
- 번호
- 삽입 위치
- 담당 질문
- 목적
- 작은 라벨
- 헤드라인
- 핵심 포인트 2~4개
- 강조 숫자·날짜
- 사진·그래픽 구성

## 2. IMAGE_COVERAGE_LEDGER — 이미지별 정보 예약

이미지 생성 전에 `IMAGE_COVERAGE_LEDGER`를 내부적으로 만든다.

각 이미지마다 다음을 기록한다.
- 담당 소제목
- 담당 질문 1개
- 이 이미지에서 처음 설명할 핵심 정보
- 사용할 숫자·날짜·조건
- 이전 이미지와 겹치면 안 되는 정보

한 이미지에 배정된 핵심 정보는 **사용 완료 정보**로 표시한다.
다음 이미지에서는 같은 정보를 다시 주요 포인트로 사용하지 않는다.

예:
- 이미지 2가 `신청기간`을 담당하면 이미지 3~6에서 신청기간을 다시 핵심 포인트로 쓰지 않는다.
- 이미지 3이 `지원 대상`을 담당하면 이미지 4에서 같은 대상조건을 다시 목록으로 반복하지 않는다.
- 이미지 4가 `금액·가격`을 담당하면 이미지 5에서 같은 금액을 다시 크게 강조하지 않는다.

문맥상 꼭 필요한 경우에만 최소한의 짧은 문구로 재언급한다.

## 3. 이미지별 단일 질문 원칙
대표 이미지를 제외한 본문 이미지는 각각 **검색자의 질문 하나만 담당**한다.

예:
- 어디에 있는가?
- 가격은 얼마인가?
- 언제 이용하는가?
- 누가 대상인가?
- 어떻게 신청하는가?
- 방문 전에 무엇을 확인해야 하는가?

한 이미지에 여러 소제목의 답을 욱여넣지 않는다.

## 4. 이미지 간 정보 중복 금지
한 이미지에서 충분히 설명한 정보는 다른 이미지에서 다시 상세하게 설명하지 않는다.

반복 최소화 항목:
- 방송일·프로그램
- 업체명·주소·전화
- 가격·금액
- 영업시간·휴무
- 신청기간
- 대상·조건
- 예약
- 재료소진
- 위치·교통
- 주차
- 주의사항

같은 숫자·날짜·조건을 여러 이미지의 주요 정보로 반복하지 않는다.
다른 이미지에서 꼭 필요하면 문맥 이해에 필요한 최소 문구만 사용한다.

이미지 2~7번은 서로 다른 소제목에 배치할 수 있어야 한다.
두 이미지를 서로 바꿔 넣어도 차이가 없을 정도로 비슷하면 중복으로 판단해 역할을 다시 배정한다.

**핵심 포인트가 50% 이상 겹치면 생성 금지**하고 자동으로 역할을 재설계한다.

## 5. 대표 이미지 예외
1번 대표 이미지는 글의 주제와 핵심 답을 압축하므로 본문 이미지와 일부 중복될 수 있다.

대표 이미지 기본:
**작은 라벨 + 메인 제목 + 핵심 정보 1개 + 대표 사진 또는 그래픽**

주소·전화·영업시간·가격표·주차·체크리스트 등 세부정보를 모두 넣지 않는다.
대표 이미지가 본문 이미지의 세부 역할을 선점하지 않도록 한다.

## 6. 본문 이미지 정보량
본문 이미지 하나에는 원칙적으로:
- 작은 라벨 1개
- 헤드라인 1개
- 핵심 포인트 2~4개
- 꼭 필요한 숫자·날짜
- 해당 내용의 사진 또는 그래픽

정보가 많으면 글씨를 작게 줄이지 말고 다른 이미지 역할로 분리한다.

## 7. 원고 밖 정보 추가 금지
이미지 다양성을 위해 최종 원고에 없는 메뉴·가격·혜택·준비물·주소·전화·운영조건·후기·법률조건 등을 임의로 추가하지 않는다.

음식점의 확인되지 않은 메뉴 구성이나 시설 모습을 실제 정보처럼 만들지 않는다.
실제 사진이 없다면 상징적·연출 이미지로 사용하며 확인되지 않은 세부사항을 사실처럼 표현하지 않는다.

이미지는 **FINAL_ARTICLE의 검증된 정보만 시각화**한다.
새로운 팩트를 만드는 단계가 아니다.

## 8. 이미지 전용 팩트체크
생성 직전 FINAL_ARTICLE과 대조한다.

검사 항목:
- 연도
- 날짜
- 금액
- 대상
- 조건
- 기관명
- 단위
- 최대·평균
- 신청기간
- 사용기간

본문에 없는 숫자나 조건을 추가하지 않는다.
`최대`, `일부`, `조건부`, `예정` 등 의미를 결정하는 표현을 삭제하지 않는다.

원고와 이미지 문구가 다르면 이미지 생성보다 **원고의 검증된 표현을 우선**한다.

## 9. 이미지 중복 최종 검사
각 이미지를 생성하기 직전에 확인한다.

1. 이전 이미지에서 이미 설명한 정보인가?
2. 이번 이미지 담당 질문이 하나로 명확한가?
3. 이전 이미지와 핵심 포인트가 절반 이상 겹치지 않는가?
4. 같은 가격·날짜·주소·영업시간·조건을 불필요하게 반복하지 않았는가?
5. FINAL_ARTICLE에 없는 정보를 추가하지 않았는가?
6. IMAGE_COVERAGE_LEDGER에서 이미 사용 완료 처리된 정보를 다시 주요 포인트로 쓰고 있지 않은가?
7. 이 이미지를 삭제하면 다른 이미지와 정보 역할이 겹쳐도 되는가? 그렇다면 역할 구분이 부족하므로 재설계한다.

중복이 발견되면 그대로 생성하지 말고 **해당 번호의 정보 역할을 자동 재배정한 뒤 생성한다.**

## 10. 이미지 생성 순서

1. FINAL_ARTICLE 확인
2. 이미지 삽입 위치 확인
3. IMAGE_COVERAGE_LEDGER 작성
4. 이미지별 단일 질문 배정
5. 중복 사전검사
6. 이미지 전용 팩트체크
7. 해당 번호 이미지 생성
8. 생성 후 다음 이미지와의 중복 가능성 업데이트

이미지 생성은 한 장씩 진행하며, 앞선 이미지의 정보 역할을 기억하고 다음 이미지에 반영한다.

## 12. REAL IMAGE MODE — 방송·연예·실존 대상

방송·연예·실존 인물·실제 장소·행사·제품처럼 **실제 모습과 정체성이 중요한 주제**는 `knowledge/07-real-image-mode.md`를 추가로 적용한다.

기본 원칙:
- 100% AI 이미지로만 채우지 않는다.
- 공식 방송사·제작사·소속사·기관·브랜드·공식 SNS·보도자료를 충분히 검색해 실제 모습을 확인한다.
- 사용권이 명확한 공식/오픈 라이선스 이미지는 실제 활용 후보로 검토한다.
- 권리 상태가 불명확한 방송 캡처·언론 사진·SNS 사진은 기본적으로 사실 확인과 시각 참고용으로만 사용한다.
- 웹에서 찾은 이미지를 직접 편집했다고 가정하지 않는다. 실제 재가공은 사용자가 업로드했거나 사용권이 명확한 원본이 작업 입력으로 제공된 경우에만 진행한다.
- 실존 인물은 공식 이미지 여러 장으로 얼굴·헤어·의상·방송 당시 맥락을 확인한 뒤, 원본 한 장을 그대로 복제하지 않는 새로운 장면·구도·정보 카드로 설계한다.
- 실제 이미지와 AI 정보 카드·그래픽을 혼합해 몰입도를 높일 수 있다.
- 저작권·초상권·사용조건이 불명확하면 `REFERENCE_ONLY`로 처리한다.

이미지 설계 후 사용자가 `1`, `2`, `3`처럼 숫자만 입력하면 추가 질문 없이 해당 번호 이미지를 생성한다.
