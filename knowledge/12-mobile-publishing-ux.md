# Knowledge — 모바일 가독성·SmartEditor 편집 UX

검토 기준일: 2026-09-22
모듈 버전: 1.0.0

## 1. 목적

이 모듈은 네이버 블로그 최종 원고를 모바일에서 읽기 쉽고, 핵심 답을 빠르게 찾을 수 있으며, SmartEditor에서 일관된 시각 구조로 편집하기 위한 운영 규칙이다.

이 모듈은 검색 노출이나 AI 인용을 보장하는 규칙이 아니다. 글자색·굵기·인용구·글자 크기는 가독성 장치로만 사용한다. AI 인용 관련 판단은 knowledge/10-ai-citation.md를 따르고, 팩트·링크·최신성은 knowledge/01-research-factcheck.md와 knowledge/03-official-links.md가 우선한다.

네이버 공식 일반 콘텐츠 가이드는 제목·소제목·문단 나누기, 짧은 문장, 중요한 정보를 본문 텍스트로 제공하는 읽기 쉬운 구조를 권장한다. SmartEditor ONE은 글꼴·크기·정렬·글자색·배경색·굵게 등의 텍스트 서식을 제공한다. 이러한 편집 기능의 존재와 검색·AI 인용 효과를 혼동하지 않는다.

## 2. 적용 단계

3단계:
- 질문형 또는 답변형 소제목 설계
- 모바일 스크롤 흐름 설계
- 이미지·링크·핵심정보 블록 위치 예약
- 인용구형 시각 소제목 적용 여부 결정

4단계:
- 첫 화면에 핵심 답 배치
- 짧은 문단과 문장으로 작성
- 질문 → 직접 답 → 근거 → 조건·예외 → 행동 순서 적용
- 이미지 속 핵심 정보를 본문 텍스트에도 남김

5단계:
- 모바일 QA
- 독자 흐름 QA
- 편집 스타일 QA
- SmartEditor 삽입 후 링크 재검증
- AI 인용을 보장하는 표현 제거

## 3. 모바일 우선 문단 규칙

- paragraph는 1~3개의 짧은 문장을 기본으로 한다.
- 가능하면 2문장 안팎을 우선한다.
- 한 문단이 스마트폰 화면에서 벽처럼 길어지면 의미 단위로 분리한다.
- 한 문장에 날짜·가격·주소·조건·예외를 과도하게 몰아넣지 않는다.
- 긴 설명은 소제목, 목록, 체크리스트, 단계로 분해한다.
- 너무 넓은 표는 피하고 모바일에서 깨지면 짧은 정보 블록으로 바꾼다.
- 텍스트와 이미지가 각각 너무 오래 연속되지 않도록 스크롤 리듬을 만든다.

권장 흐름:
제목 → 짧은 도입 → 핵심 요약 → 대표 이미지 → 주요 소제목 → 짧은 본문 → 관련 이미지/정보 → 다음 소제목 → 행동 링크 → 방문·이용 체크 → 마무리.

## 4. 첫 화면 규칙

도입은 장황한 인사보다 독자의 질문과 핵심 답을 우선한다.

기본 순서:
1. 지금 이 글을 볼 이유
2. 핵심 답 또는 가장 중요한 변화
3. 이 글에서 확인할 정보

검색·AI 요약 친화성을 위해 핵심 답을 숨기지 않는다. 다만 짧게 만들려고 조건·예외·기준일을 삭제하지 않는다.

## 5. 독자가 계속 읽고 싶은 구조

정보를 작성자가 조사한 순서가 아니라 독자가 궁금해하는 순서로 배치한다.

방송맛집·여행형 예:
- 왜 화제가 됐는가
- 방송에서 무엇이 소개됐는가
- 현재도 같은 상호·장소인가
- 현재 가격은 얼마인가
- 영업시간·휴무·브레이크타임·라스트오더는 무엇인가
- 주차·예약·웨이팅 등 방문 전 확인할 점은 무엇인가
- 네이버 장소와 공식 영상은 어디인가
- 근처 여행지와 실제 동선은 어떤가

정보형·정책형은 대상 → 금액/조건 → 기간 → 신청/이용 방법 → 예외 → 공식 링크 순으로 조정한다.

낚시성 문구, 근거 없는 감탄, 같은 결론의 반복으로 체류를 억지로 늘리지 않는다.

## 6. 소제목 규칙

소제목 하나는 독자 질문 하나 또는 핵심 답 하나를 담당한다.

좋은 예:
- 전현무계획4에 나온 전주 물갈비집은 어디일까?
- 현재 물갈비 가격은 얼마일까?
- 영업시간과 휴무일은?
- 방문 전에 확인할 점은?

피할 예:
- 정보
- 설명
- 기타
- 꼭 보세요
- 대박 정보

질문형 소제목은 자연스러운 경우에만 사용한다. 모든 소제목을 억지로 물음표로 끝내지 않는다.

## 7. 인용구형 시각 소제목

사용자가 선호하는 왼쪽 세로선 형태의 SmartEditor 인용구 디자인을 주요 소제목의 시각 스타일로 사용할 수 있다.

규칙:
- 실제로는 SmartEditor의 인용구/유사 시각 블록을 사용하고 '┃' 같은 문자를 직접 입력해 흉내내지 않는다.
- 실제 타인의 발언을 인용한 것처럼 오해되지 않게 출처 인물을 임의로 붙이지 않는다.
- 글의 모든 짧은 라벨에 남용하지 않고 주요 섹션에 일관되게 사용한다.
- 실제 인용문을 넣을 때는 시각 소제목과 구분하고 출처를 명확히 한다.
- 사용 중인 편집기에서 인용구가 의미상 혼동되거나 레이아웃이 깨지면 일반 소제목 + 구분선/강조 스타일로 대체한다.

인용구 디자인 자체를 SEO·AI 인용 신호라고 주장하지 않는다.

## 8. 글자 크기·굵기·정렬

SmartEditor에서 실제 사용 가능한 값 안에서 조정한다.

기본 방향:
- 본문: 모바일에서 무리 없이 읽히는 기본 크기. 별도 설정이 없으면 약 15 수준을 기준으로 삼되 고정 수치로 강제하지 않는다.
- 정렬: 정보형 본문은 왼쪽 정렬을 기본으로 한다.
- 소제목: 본문보다 한 단계 이상 눈에 띄게 하고 주요 소제목은 굵게 사용 가능하다.
- 굵기: 가격·날짜·영업시간·휴무·핵심 조건처럼 스캔이 필요한 정보에 제한적으로 사용한다.
- 한 문단 전체를 굵게 처리하지 않는다.

## 9. 색상 규칙

색상은 검색 순위나 AI 인용 조작용이 아니라 독자의 시선 안내용이다.

권장 체계:
- 본문: 검정 또는 진한 회색. 편집기 팔레트에서 #222222~#333333에 가까운 계열.
- 주요 소제목: 진한 회색 또는 차분한 네이비 계열 한 가지.
- 포인트: 한 글에서 기본 1개 색상. 가격·날짜·핵심 숫자·중요 조건처럼 필요한 곳에만 사용.
- 주의: 꼭 필요한 경우에만 차분한 짙은 적색 계열.

금지:
- 키워드마다 다른 색
- 형광색 남용
- 빨강·파랑·초록·보라를 한 문단에 혼합
- 검색 키워드를 색으로 반복 강조
- 색상만으로 의미를 전달하고 텍스트 설명을 생략

색상값은 에디터가 지원하는 팔레트가 다를 수 있으므로 가장 가까운 색을 선택한다.

## 10. 핵심 요약 블록

도입 뒤에 실제 도움이 될 때만 3~6개 핵심 정보를 짧게 요약한다.

예:
- 방송: 프로그램·회차·방송일
- 현재 상호
- 대표 메뉴·가격
- 주소
- 영업시간
- 확인 기준일

요약 블록의 정보는 본문과 일치해야 한다. 요약 때문에 같은 내용을 본문에서 반복 설명하지 않는다.

## 11. AI가 읽기 쉬운 정보 구조

AI 인용 효과는 검증 대상이며 보장하지 않는다. 다만 독자와 기계가 의미를 파악하기 쉬운 다음 구조를 권장한다.

질문 또는 명확한 소제목
→ 첫 문장에서 직접 답
→ 구체적 숫자·날짜·장소
→ 조건·예외
→ 근거 또는 행동 링크

숫자는 가능하면 대상 + 값 + 단위 + 기준 시점 + 적용 조건을 함께 쓴다.

나쁜 예:
- 가격은 이 정도예요.

좋은 예:
- 2026년 9월 22일 확인 기준, 물갈비 1인분 가격은 15,000원입니다.

과거 방송 정보와 현재 운영 정보는 섞지 않고 별도로 표시한다.

## 12. 이미지와 텍스트

- 대표 이미지는 도입·핵심요약 뒤에 둔다.
- 본문 이미지는 설명하는 문단 가까이에 배치한다.
- 이미지 여러 장을 연속으로 몰아넣지 않는다.
- 가격·주소·기간·예외 같은 핵심정보는 이미지에만 넣지 않고 본문에도 작성한다.
- AI 생성 이미지는 실제 매장·방송 캡처·방문 증거처럼 표현하지 않는다.

## 13. SmartEditor 링크 삽입 후 재검증

knowledge/03-official-links.md의 LINK VERIFY와 LINK RECHECK를 그대로 적용한다.

추가로 실제 SmartEditor에 링크를 삽입한 뒤:
1. 링크 문구와 목적지가 일치하는지 확인한다.
2. 가능하면 새 탭에서 실제로 연다.
3. 네이버 플레이스는 정확한 상호·주소·지점인지 확인한다.
4. 방송·YouTube는 메인 채널이 아니라 관련 개별 영상/회차인지 확인한다.
5. 편집 과정에서 링크가 삭제되거나 다른 URL로 바뀌지 않았는지 확인한다.
6. 추적 파라미터가 불필요하면 제거한다.
7. 확인할 수 없는 링크는 추정해서 만들지 않는다.

발행 직전 링크가 실패하면 교체 또는 삭제하고 관련 본문도 함께 수정한다.

## 14. MOBILE_READER_QA

발행 전 확인한다.

- 첫 화면에서 핵심 답을 찾을 수 있는가?
- 도입이 길지 않은가?
- 문단이 스마트폰 화면에서 벽처럼 보이지 않는가?
- 각 소제목만 읽어도 글 흐름을 이해할 수 있는가?
- 인용구형 소제목이 실제 인용문처럼 오해되지 않는가?
- 이미지와 텍스트가 자연스럽게 교차하는가?
- 긴 표가 모바일 가독성을 해치지 않는가?
- 굵은 글씨와 색상이 과하지 않은가?
- 핵심 숫자·날짜·주소를 빠르게 찾을 수 있는가?
- 같은 정보를 여러 형식으로 반복하지 않았는가?

FAIL이면 서식을 더 추가하는 대신 구조를 먼저 단순화한다.

## 15. CITATION_EXTRACTABILITY_QA

이는 네이버 공식 점수나 인용 확률이 아니다.

- 제목·소제목·첫 답이 같은 주제를 말하는가?
- 핵심 답에 주어·대상·시점·조건이 포함됐는가?
- 질문 아래 첫 문장에서 답을 찾을 수 있는가?
- 가격·날짜·주소·영업정보가 텍스트로 존재하는가?
- 과거와 현재가 구분됐는가?
- 중요한 주장 가까이에 실제 근거가 있는가?
- 글자색·인용구·굵기를 인용 알고리즘 조건처럼 설명하지 않았는가?

## 16. 편집 자동화 에이전트 규칙

Aside 등 브라우저 자동화 에이전트가 SmartEditor를 조작하는 경우에도 이 모듈을 적용할 수 있다.

- 5단계 FINAL_ARTICLE의 사실을 임의로 바꾸지 않는다.
- 외부 서식을 그대로 복붙해 깨뜨리기보다 깨끗한 텍스트를 넣고 에디터 안에서 서식을 적용한다.
- 인용구형 소제목, 본문 크기, 굵기, 포인트 색상은 이 문서의 규칙을 따른다.
- 모바일 미리보기가 제공되면 최종 QA에 사용한다.
- CAPTCHA·재인증·본인확인·보안 승인 등은 우회하지 않는다.
- 실제 발행 가능 여부와 권한은 사용하는 브라우저·서비스 정책을 따른다.
