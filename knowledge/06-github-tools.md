# Knowledge — GitHub 검증 도구에서 가져온 품질 게이트

이 파일은 외부 도구 설치를 강제하지 않는다.
GitHub에서 장기간 사용되고 최근까지 유지보수되는 도구의 검증 철학을 `blog-master-skill` 내부 규칙으로 흡수한다.

참고 프로젝트:
- Vale — https://github.com/vale-cli/vale
- textlint — https://github.com/textlint/textlint
- lychee — https://github.com/lycheeverse/lychee
- markdownlint-cli2 — https://github.com/DavidAnson/markdownlint-cli2

## 1. STYLE LINT — Vale 방식
게시용 원고 초안 후 문체 규칙을 독립적으로 검사한다.

검사:
- 과장·낚시 표현
- 같은 의미의 반복
- 불필요한 접속어·군더더기
- 모호한 지시어
- 용어 표기 불일치
- 지나치게 긴 문장
- 같은 문장 종결 패턴의 과도한 반복
- 제목과 본문의 어조 불일치

자동 수정 시 중요한 조건·예외·숫자는 삭제하지 않는다.

## 2. MODULAR TEXT RULES — textlint 방식
자연어 검사를 하나의 거대한 판단으로 처리하지 않고 규칙별로 나눠 검사한다.

권장 규칙 모듈:
- 중복 문장 검사
- 중복 주장 검사
- 동일 키워드 과반복 검사
- 문장 호흡 검사
- 숫자와 단위 결합 검사
- 예정/확정 표현 검사
- 최대/평균/일반값 혼동 검사
- 소제목과 문단 답변 일치 검사
- 내부 참조 코드 노출 검사

한 규칙에서 FAIL이 나면 전체 글을 다시 쓰기보다 해당 오류만 먼저 수정한다.

## 3. LINK HEALTH — lychee 방식
독자용 공식 링크는 최종 원고 삽입 전과 게시 직전에 별도로 검사한다.

검사:
1. URL이 실제로 열리는가
2. 404·오류·종료 페이지가 아닌가
3. 리다이렉트 후 목적지가 맞는가
4. HTTPS 공식 페이지를 우선할 수 있는가
5. 현재 연도·현재 제도·현재 상품 페이지인가
6. 신청/예약/조회 목적과 실제 페이지가 일치하는가
7. 동일 링크를 불필요하게 반복하지 않았는가
8. 메인 홈페이지보다 직접 행동 페이지가 있는가

링크가 열리기만 한다고 PASS 처리하지 않는다.
**정상 접속 + 목적 일치 + 최신성**이 모두 확인되어야 한다.

## 4. STRUCTURE LINT — markdownlint-cli2 방식
게시용 원고의 구조를 독립적으로 검사한다.

검사:
- 제목이 하나의 명확한 주제를 갖는가
- 소제목 계층이 자연스러운가
- 빈 소제목이 없는가
- 같은 이름의 소제목이 반복되지 않는가
- 목록 형식이 섞여 읽기 어렵지 않은가
- 표가 모바일에서 지나치게 넓지 않은가
- 한 문단이 과도하게 길지 않은가
- 코드블록·검색ID·도구ID·시스템 참조가 게시 원고에 남지 않았는가

네이버 게시용 원고에 Markdown 문법을 강제로 노출하라는 뜻이 아니다.
내부 구조 검증에만 이 원칙을 사용한다.

## 5. FINAL FOUR-GATE
5단계 최종 확정 직전에 다음 순서로 검사한다.

1. `STYLE_LINT`
2. `TEXT_RULE_LINT`
3. `LINK_HEALTH` — 링크가 필요한 글만
4. `STRUCTURE_LINT`

하나라도 FAIL이면 해당 부분을 직접 수정하고 다시 검사한다.

## 6. 외부 도구 직접 실행이 가능한 환경
실행 환경에 Vale, textlint, lychee, markdownlint-cli2가 실제 설치되어 있고 사용 가능한 경우 보조 검증으로 활용할 수 있다.

단:
- 외부 도구 결과를 무조건 정답으로 간주하지 않는다.
- 한국어 문맥과 사용자 지침이 우선한다.
- 도구가 없더라도 위 품질 게이트 자체는 항상 수행한다.
- 외부 도구 설치 여부 때문에 1~6단계 핵심 기능을 생략하지 않는다.
