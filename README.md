# NAVER Blog Master Skill v4.1

네이버 블로그 글쓰기·운영을 위한 **AI 편집국 Skill**입니다.

기본 운영은 이제 `AUTO FULL`로 모든 단계를 한 번에 끝내지 않습니다.

```text
$naver-blog-master AUTO FULL
지금 조회수를 최대한 노릴 수 있는 주제를 찾아서 글을 완성해줘.
```

위처럼 요청해도 기본적으로 **1~4단계까지만 자동 실행한 뒤 멈춥니다.**

그다음:

```text
5단계
```

을 입력하면 최종 글을 작성하고,

```text
6단계
```

을 입력하면 이미지 계획·제작 단계로 넘어갑니다.

## v4.1 핵심 변화

v4.1은 과거 단계별 진행에서 안정적으로 작동하던 방식을 자동화에 적용합니다.

### 기본 흐름

```text
AUTO 1~4
↓
1단계 주제·트래픽 조사
↓
2단계 키워드·제목·검색의도
↓
3단계 팩트·출처·최신성 검증
↓
4단계 링크 검증 + 글 구조 확정 + LOCK
↓
멈춤
↓
사용자: 5단계
↓
최종 글 작성
↓
사용자: 6단계
↓
이미지 계획/생성
```

## 왜 4단계에서 멈추나요?

AUTO FULL로 주제 조사부터 최종 글까지 한 번에 처리하면, AI가 중간 상태를 압축하면서 다음 문제가 생길 수 있습니다.

- 검증 링크가 최종 글에서 빠짐
- 팩트가 조사 단계와 글쓰기 단계 사이에서 바뀜
- 제목/각도가 중간에 변형됨
- 이미 다룬 주제를 다시 선택함
- 이미지 계획까지 한꺼번에 처리하며 본문 완성도가 떨어짐

v4.1은 4단계에서 핵심 자산을 잠근 뒤, 5단계는 **잠긴 자료로 글만 쓰도록** 분리합니다.

## 4단계 LOCK

4단계가 끝나면 다음을 잠급니다.

- `TOPIC_LOCK`
- `TITLE_LOCK`
- `FACT_SET = LOCKED`
- `SOURCE_LEDGER = LOCKED`
- `LINK_SET = LOCKED`
- `OUTLINE = LOCKED`

5단계에서는 원칙적으로 새 주제를 고르거나 검증된 링크를 임의로 바꾸지 않습니다.

## CHAT_TOPIC_LEDGER — 같은 채팅의 중복 주제 방지

현재 채팅에서 이미 선정·작성·진행한 주제를 기록합니다.

기록 항목:
- 메인 주제
- 메인 키워드
- 제목/제목 후보
- 핵심 엔티티
- 검색의도
- 핵심 각도
- 시점·지역·이벤트
- 상태

새 주제 후보를 만들 때 먼저 `CHAT_TOPIC_LEDGER`와 비교합니다.

### 중복으로 보는 경우

- 제목만 다르고 사실상 같은 주제
- 같은 엔티티 + 같은 검색의도
- 같은 정책/행사/맛집/제품을 같은 각도로 반복
- 숫자나 표현만 바꾼 변형 글
- 같은 장소를 거의 같은 추천 관점으로 재작성

### 새 글로 허용하는 경우

- 공식 정보가 의미 있게 변경됨
- 가격·일정·정책·신청기간이 새로 바뀜
- 검색의도가 기존 글과 명확히 다름
- 비교편·후속편·실전편처럼 새로운 독자 질문을 해결함

이 경우 `UPDATE` 또는 `FOLLOW-UP`으로 분류하고 기존 글과 차이를 먼저 정의합니다.

## 1단계 — 주제·트래픽

1단계에서는 후보 10~20개를 만든 뒤:

1. CHAT_TOPIC_LEDGER 대조
2. 완전 중복 제거
3. 유사 중복 제거
4. 남은 후보만 시의성·검색수요·경쟁·확장성 평가
5. 공식자료 확보 가능성 확인
6. 최종 주제 선정

확인되지 않은 네이버 검색량 숫자를 만들어내지 않습니다.

## 2단계 — 키워드·제목·검색의도

- 메인 키워드
- 보조 키워드
- 독자 질문
- 검색의도
- 제목 후보
- 최종 제목
- 첫 화면 핵심답
- 계속 읽을 이유

를 확정합니다.

## 3단계 — 팩트체크

공식자료를 우선합니다.

출처 우선순위:
1. 정부·공공기관·공식 홈페이지·공식 통계·공식 방송
2. 주요 언론·전문기관·연구기관
3. 블로그·SNS·커뮤니티

반드시 확인할 수 있는 항목:
- 날짜
- 가격
- 신청기간
- 영업시간
- 주소·지점
- 이전·폐업·상호변경
- 행사 일정
- 방송 정보
- 공식 영상
- 링크

확인되지 않은 사실은 추정해서 채우지 않습니다.

## 4단계 — 링크 검증 + 구조 확정

먼저 필요한 링크 종류를 정합니다.

예:
- 지원금 → 신청, 대상조회, 공식안내
- KTX → 예매/잔여석, 예약대기, 공식공지
- 맛집 → 지도, 예약, 공식매장정보
- 여행 → 지도, 교통/주차, 공식관광, 티켓

그다음 각 링크를 실제로 열어:
- 정상 연결
- 공식 도메인
- 목적 일치
- 최신 페이지
- 종료 여부
- 모바일 행동 가능 여부

를 확인합니다.

마지막으로 본문 구조와 링크 삽입 위치를 확정하고 `LINK_SET`과 `OUTLINE`을 잠급니다.

## 5단계 — 최종 글 작성

사용자가 `5단계`라고 입력했을 때만 진행합니다.

5단계에서는:
- 1~4단계에서 LOCK된 자료만 사용
- 주제 임의 변경 금지
- 검증 링크 임의 교체 금지
- 링크 누락 금지
- 모바일 가독성 유지
- Answer First
- 체류 추가가치
- No-Search-Back
- 2차 팩트체크

를 적용합니다.

핵심은 **4단계에서 확정한 링크를 5단계에서 그대로 본문에 넣는 것**입니다.

## 6단계 — 이미지

5단계 글이 확정된 뒤에만 진행합니다.

- 본문 소제목별 이미지 역할 정의
- 중복 정보 방지
- 실존 인물·방송·장소 사실 확인
- 저작권·사용권 검수
- 개별 이미지 번호 부여
- 이미지 한 장씩 생성

`1`, `다음`, `계속`으로 진행합니다.

## 유지되는 품질 규칙

v4.1에서도 다음은 그대로 유지됩니다.

- Requirement Ledger
- 공식자료 우선 팩트체크
- 교차검증
- 최신성 확인
- 링크 실제 오픈 검증
- 모바일 퍼스트
- 검색의도 반영
- Answer First
- Retention Architecture
- No-Search-Back
- 실제 내부링크만 사용
- 이미지 사실·권리 검수
- Final Control Tower
- 광고 클릭 유도 금지

## 권장 사용법

가장 안정적인 방식:

```text
$naver-blog-master AUTO 1-4
지금 조회수를 최대한 노릴 수 있는 새 주제를 찾아줘.
```

또는 기존 명령:

```text
$naver-blog-master AUTO FULL
지금 조회수를 최대한 노릴 수 있는 주제를 찾아서 글을 완성해줘.
```

을 입력해도 v4.1에서는 1~4단계까지만 실행하고 멈춥니다.

이후:

```text
5단계
```

그다음:

```text
6단계
```

으로 진행합니다.
