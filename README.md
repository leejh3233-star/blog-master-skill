# NAVER Blog Master Skill v3.9

네이버 블로그 글쓰기·운영을 위한 **AI 멀티에이전트 편집국 Skill**입니다.

```text
$naver-blog-master AUTO FULL
지금 조회수를 최대한 노릴 수 있는 주제를 찾아서 글을 완성해줘.
```

## v3.9 핵심 변화

v3.9는 자동화 중 중요한 과정이 합쳐지거나 생략되는 문제를 막기 위해 **Micro-Gate 구조**를 사용합니다.

자동화의 의미를 이렇게 정의합니다.

> 사용자가 단계마다 다시 명령하지 않아도 되지만, AI 내부에서는 모든 필수 단계를 순서대로 끝까지 실행한다.

각 단계는 반드시:

```text
작업
↓
독립 검수
↓
승인
↓
다음 단계
```

순서로 진행합니다.

PASS가 아니면 다음 단계로 넘어가지 않습니다.

## 링크는 다시 단순하게 처리합니다

기본값은 **글쓰기 블록 안에서 문구 자체가 클릭되는 링크**입니다.

예:

```text
[코레일 승차권 예매 바로가기](검증된 URL)
```

사용자 화면에서는 주소를 길게 보여주는 대신 `코레일 승차권 예매 바로가기`라는 문구가 클릭 가능한 형태가 되는 것을 목표로 합니다.

TXT/HTML·별도 링크 패널은 기본값이 아닙니다.
현재 출력 환경에서 inline clickable link가 실제로 실패하거나 사용자가 별도로 요청할 때만 fallback으로 사용합니다.

## 링크 단계는 왜 더 쪼갰나요?

이전에는 `링크 조사/검증`을 한 덩어리로 처리하면서 다음 문제가 생길 수 있었습니다.

- 필요한 링크 종류 자체가 빠짐
- URL은 찾았지만 실제로 열지 않음
- 공식 페이지가 아닌 메인페이지로 대체
- 링크는 검증했지만 본문에 안 넣음
- 본문에 넣었지만 다른 URL로 바뀜

v3.9에서는 이를 각각 별도 단계로 나눴습니다.

### 3B — LINK REQUIREMENT MAP
먼저 **무슨 링크가 반드시 필요한지** 정의합니다.

예:
- KTX 글 → 예매/잔여석, 예약대기, 공식 공지
- 지원금 글 → 신청, 대상조회, 공식 안내
- 맛집 글 → 네이버지도, 예약, 공식 메뉴

### 3D — LINK VERIFIER PASS 1
각 필수 링크를 실제로 열어:
- 정상 연결
- 공식 도메인
- 목적 일치
- 현재 연도/시즌
- 종료 여부
을 확인합니다.

### 5B — INLINE CLICKABLE LINK COMPOSER
검증된 URL을 발행용 글쓰기 블록의 적절한 위치에 **클릭 가능한 문구 링크로 삽입**합니다.

### 5C — LINK VERIFIER PASS 2
본문에 실제 삽입된 링크를 다시 확인합니다.

LINK-CRITICAL 주제는 발행 직전에도 다시 확인합니다.

## 암묵적 PASS 금지

`문제 없어 보인다`, `링크가 있는 것 같다`는 PASS가 아닙니다.

각 Gate는:
- PASS
- FAIL
- BLOCKED

중 하나를 명시적으로 반환해야 합니다.

FAIL이면 정확한 이전 단계로 되돌아갑니다.

## 링크 위치 원칙

기본:

> 답은 초반에, 깊이는 중간에, 행동 링크는 후반에.

- URGENT: 상단 10~25%
- STANDARD: 후반 60~90%
- FACT-CHECK: 관련 설명 뒤 또는 후반
- INTERNAL: 실제 발행글만 중반 이후

## 최종 출력

AUTO FULL의 정상 결과는:

1. 최종 주제·제목·키워드
2. **클릭 가능한 문구 링크가 포함된 하나의 발행용 글쓰기 블록**
3. 검증 링크팩
4. 이미지 제작팩
5. Requirement Ledger 요약
6. Final QA
7. 이미지 큐 READY

입니다.

링크팩은 관리용일 뿐 **본문 링크를 대신하지 않습니다.**
